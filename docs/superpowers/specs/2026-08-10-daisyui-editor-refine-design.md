# DaisyUI 会员证编辑器 UI 精修设计

## 1. 目标与边界

本次工作只精修 Fabric 会员证编辑器的视觉层、布局层和头像数值控件，不改变会员证模板、画布坐标、编辑数据流、导出行为、路由语义或无障碍契约。

目标是让编辑器呈现为清晰、紧凑的“工作室工具”，并统一使用项目已经安装的 DaisyUI 组件语言。会员证成品仍是页面视觉主角，界面本身保持克制。

明确不做：

- 不重画会员证模板或修改模板元素坐标。
- 不新增业务字段、撤销历史、保存草稿或云端功能。
- 不修改 Fabric 画布事件、导出倍率或剪贴板策略。
- 不引入新的 UI 组件库、图标库或主题运行时。

## 2. 视觉方向：DaisyUI 工作室编辑器

页面采用 DaisyUI 的语义色和组件原语，而不是继续维护一套平行的自定义控件系统。

- 页面外层使用安静的深色工作台背景，突出白色会员证预览。
- 控制区采用 `card`、`bg-base-100`、`border-base-300` 和轻量阴影。
- 主色只用于当前模板、当前选项、焦点和主要导出操作。
- “保存 PNG”是唯一主按钮；“复制图片”是次按钮；重置操作使用低强调样式。
- 状态使用 `badge`、`alert` 和语义色，不再以低对比文字散落在深色背景上。
- 文字层级使用 DaisyUI/Tailwind 的现有字体栈，不下载新字体。
- 动效只保留短促的颜色、边框和阴影过渡，并尊重 `prefers-reduced-motion`。

## 3. 页面结构

### 3.1 桌面端

工作区最大宽度保持 90rem，结构为紧凑顶栏与双栏编辑区：

```text
┌─────────────────────────────────────────────────────┐
│ 标题 / 当前状态      [新版][经典版]     [全部重置] │
├────────────────────────────────┬────────────────────┤
│                                │ 编辑控制台         │
│       会员证预览工作台          │ [基本信息][头像]   │
│                                │ 表单               │
│                                ├────────────────────┤
│                                │ 状态 / 导出        │
└────────────────────────────────┴────────────────────┘
```

- 顶栏从高大的介绍卡收紧为单行命令栏；窄桌面允许自然换行。
- 预览列约占 65%，右侧控制列约占 35%。
- 预览容器使用深色舞台、柔和内边框和充足留白，不再套多层同色白卡。
- 右侧把检查器、状态和导出组织为同一视觉栈，保持一致圆角和间距。

### 3.2 手机端

- 顶栏固定为两行：标题/状态与模板/重置操作。
- 预览在上、控制区在下；完整预览入口仍保留。
- 表单、状态和导出均占满可用宽度。
- 导出操作在移动端保持可触达并处理底部安全区。
- 所有交互控件最小触摸尺寸仍为 44×44 CSS 像素。

## 4. 组件映射

- `CardEditorWorkspace`：页面网格、工作台背景、控制列分组和状态呈现。
- `CardToolbar`：紧凑命令栏，使用 DaisyUI 按钮组与状态徽标。
- `FullPreviewShell`：预览舞台与全屏入口，不改变 slot 生命周期或对话框语义。
- `FabricCardCanvas`：只调整外观容器，不改变 Canvas 生命周期和事件桥接。
- `CardInspector`：DaisyUI 卡片、tabs、输入框、文件输入和头像拉杆。
- `ExportActions`：主次操作层级、工作状态和复制能力提示。
- `EditorDialog`：只在必要处对齐 DaisyUI 卡片/按钮视觉，不替换现有焦点管理实现。
- `CardEditorView`：继续只负责组合状态与工作流，不承载新的展示逻辑。

所有 props 和 emits 保持不变，继续遵循 props down / events up。

## 5. 头像拉杆交互

头像的 `left`、`top`、`scale` 从单独数值输入改为 DaisyUI `range` 与紧凑数值输入的组合：

- 拉杆用于快速调节，数值框用于键盘精调。
- `left` 与 `top` 使用模板坐标范围 `-960` 到 `960`，步进为 `0.01`，以兼容现有小数模板坐标。
- `scale` 使用 `0.1` 到 `3`，步进为 `0.01`。
- 每次输入仍发送完整、不可变的 `AvatarTransform`。
- 现有几何层继续负责 cover clamp；UI 不复制头像边界算法。
- props 回传被 clamp 后的值时，拉杆和数值框同步回实际值。
- 每个拉杆有可见标签、当前值和屏幕阅读器名称。
- disabled/busy 状态同时禁用拉杆和数值框。

## 6. 状态与错误

- `loading`：预览维持现有骨架/禁用行为，控制列显示 DaisyUI loading 状态。
- `ready`：使用低强调成功徽标，不占用大块空间。
- `degraded` 与 `error`：使用语义 `alert`，保留现有恢复文案。
- 字段校验错误继续与输入通过 `aria-describedby` 关联，并使用 DaisyUI error 边框与错误文本。
- 上传、复制和导出状态继续由现有 `aria-live` 区域播报。
- busy 状态不改变布局，按钮使用 loading 指示并禁止重复提交。

## 7. 测试与验收

### 7.1 自动化测试

- 组件测试先锁定 DaisyUI 关键类、主次按钮层级和状态呈现。
- 头像三组 range 控件必须验证范围、步进、值同步、disabled 和 emit payload。
- 保留既有 props/emits 身份、焦点、键盘、响应式和无障碍回归测试。
- 运行全部 unit/component tests、`vue-tsc`、ESLint 和 Prettier。

### 7.2 浏览器验收

- 桌面：1440×1000，检查层级、同屏编辑、无横向溢出和 sticky 行为。
- 手机：390×844，检查单栏、触摸尺寸、预览可见性和安全区。
- 当前版和经典版各检查一次。
- 检查默认、dirty、busy、field error、resource error 和 copy unavailable 状态。
- 检查键盘 focus、Tab 顺序、控制台错误和布局溢出。
- 完成后只执行一次 Impeccable mechanical detector，再进行最多一轮集中修正与确认截图。

## 8. 验收标准

- 页面明显使用统一的 DaisyUI 组件语言，而非自绘按钮和输入框拼接。
- 会员证预览仍是视觉焦点，编辑器外壳不与卡面争夺注意力。
- 顶栏、检查器、状态和导出区有清晰的主次关系。
- 数值头像控制同时支持拉杆快速调节与数值精确输入。
- 桌面和手机无横向溢出，核心操作不被遮挡。
- 现有编辑、模板切换、重置、上传、复制、导出和全屏预览行为不变。
- 自动化测试、类型检查、静态检查和浏览器验收全部通过。
